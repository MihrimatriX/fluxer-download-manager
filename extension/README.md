# Fluxer browser extension (Chromium, MV3)

Captures browser downloads and context-menu actions and hands them to the Fluxer app through the
native messaging host. Message contracts: `src/protocol.ts` (mirrors `docs/ARCHITECTURE.md` §5.2).

## Build & test

```sh
npm install
npm run build   # icons + type-check + Vite → dist/ (loadable unpacked extension)
npm test        # Vitest unit tests
node ../tools/e2e-extension.mjs          # end-to-end in a throw-away Chrome profile (DevTools pipe)
node ../tools/e2e-extension.mjs --send   # also sends to the app: dev instance + a dev host registration only
```

## Load unpacked

1. Open `chrome://extensions` (or `edge://extensions`), enable **Developer mode**.
2. **Load unpacked** → select `extension/dist`.

## Layout

- `src/background.ts` – service worker: download capture, context menus, notifications.
- `src/capture.ts` – pure capture decision + message building (unit-tested).
- `src/collector.ts` – generic page resource collector (unit-tested, no site-specific code).
- `src/media.ts` – media sniffing from response headers: progressive files and HLS/DASH manifests; segments,
  tiny files and YouTube range requests are ignored (unit-tested).
- `src/batch.ts` – batch download: page links → typed file list and filters (unit-tested).
- `src/content.ts` – content script (classic IIFE build): Alt-key bypass tracking, resource collection, and the
  "Download with Fluxer" button over videos (closed shadow root, constructed stylesheet, no innerHTML).
- `src/popup/` – toolbar popup: Downloads (live list: pause/resume/open/folder/remove), This page (the page's
  video via yt-dlp, captured media, batch download with type filters), Settings.
- `src/locales.test.ts` – every message key in use exists in every locale.
- `public/` – manifest, `_locales/{en,tr}`, icons (generated by `scripts/icons.mjs`).

Hold **Alt** while clicking a link to leave that download to the browser.
